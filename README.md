# 空品測站連續觀測台

三個環境部資料來源並列：

| 來源 | 輸入什麼 | 解析度 | 範圍 |
|---|---|---|---|
| **智慧城鄉空品微型感測器** | 裝置編號（**不是**裝置名稱），例如 `13580653094` | 1–3 分鐘（依裝置而異） | 全國約 10,999 點；API 只留近 2 小時，更早的由 repo 歷史檔補上 |
| **國家空品測站**（環境部開放資料） | 測站名稱，例如 `板橋` | 每小時，可回溯**約 4 天** | **77 站全有**，需 api_key |
| **國家空品測站 STA**（民生公共物聯網） | 測站名稱，例如 `新莊` | 每小時，只留**近 2 小時** | 66 站，免金鑰 |

⚠️ 三個 API 都**只保留最近幾小時到幾天**的觀測值。微型感測器要看跨日資料，
靠的是 repo 裡由 GitHub Actions 事先萃取好的歷史檔（見下方〈微型感測器的跨日資料〉）；
國家測站請用「環境部開放資料」那個分頁（約 4 天）。

同一個測項（例如兩邊都有的 PM2.5）會疊在同一張圖上，用不同顏色區分測站，
可以直接看微型感測器相對於法規等級測站的偏差方向與時間結構。

純靜態網頁，無後端、無 build step。除了「環境部開放資料」那個分頁需要 api_key 之外都免金鑰；
跨日的歷史資料由 GitHub Actions 事先產好放進 repo，網頁只是同源讀檔。

## 檔案

| 檔案 | 用途 |
|---|---|
| `index.html` | 整個網站，單一檔案 |
| `scripts/hist_extract.py` | 從 history.colife.org.tw 萃取指定裝置的歷史觀測值（只用 Python 標準函式庫） |
| `.github/workflows/hist-backfill.yml` | 手動回填／探測（五種模式） |
| `.github/workflows/hist-daily.yml` | 每日增量抓取（台灣時間 05:00） |
| `.github/workflows/api-append.yml` | 每小時把 API 即時值併進歷史檔（補「今天」的缺口） |
| `data/` | 上面兩個 workflow 的產出，網頁以同源方式讀取 |
| `worker.js` | Cloudflare Worker CORS proxy，**只有被 CORS 擋下時才需要** |
| `README.md` | 本說明 |

## 部署到 GitHub Pages

```bash
# 1. 建 repo（名稱自取，例如 air-observer）
git init
git add index.html worker.js README.md scripts .github
git commit -m "空品測站連續觀測台"
git branch -M main
git remote add origin https://github.com/<你的帳號>/air-observer.git
git push -u origin main
```

2. GitHub repo → **Settings → Pages**
3. Source 選 **Deploy from a branch**，Branch 選 `main` / `(root)`，Save
4. 約 1 分鐘後上線：`https://<你的帳號>.github.io/air-observer/`

> 檔名必須是 `index.html`（放在 repo 根目錄），Pages 才會直接開啟。

## 微型感測器：裝置編號怎麼來

在**空氣網**（<https://wot.moenv.gov.tw>）地圖上點任一感測點，詳細面板中間那串粗體字就是裝置編號：

```
13580653094          ← 純數字，對應 properties/stationID
TW040203A0506884     ← TW 開頭，對應 properties/locationId
```

**這是裝置編號，不是裝置名稱。** 輸入「中山國小」「XX 路口」之類的地點名稱查不到，
那些是顯示用的名稱，不是 API 的查詢鍵。

輸入值會依序嘗試四種比對，命中即停：

| 順序 | 比對欄位 | 範例 |
|---|---|---|
| 1 | `properties/locationId` | `TW040203A0506884` |
| 2 | `properties/stationID` | `13580653094` |
| 3 | `name` 完全相符 | `智慧城鄉空品微型感測器-13580653094` |
| 4 | 名稱片段（`substringof` / `contains`） | 部分關鍵字 |

也可以展開「改用座標找附近的微型感測器」，用經緯度 + 半徑搜尋。

## 國家空品測站：打測站名稱

切到「國家空品測站」分頁，直接輸入測站名稱：

```
板橋    萬華    三重    土城    菜寮    新莊
```

或按 **列出國家測站**：會把整份清單抓回來（分頁抓完，不截斷），
**先選縣市、再點測站的「加入」**，不用記名稱。

打字查詢也是拿同一份清單做本機比對，所以只要清單裡有的站都找得到。

> ⚠️ **這個資料集只有 66 站，不是環境部全網的 77 站。**
> 以頁面的「診斷」按鈕實測：不加任何過濾條件時 `@iot.count` 就是 66，
> 查「板橋」的三種寫法都回 0 筆——**板橋、土城等站不存在於這個服務**，換寫法查不到。
> 新北市可用的是：新莊、菜寮、林口、三重、永和、富貴角。
>
> 查不到某站時，本頁會列出**離你已加入的微型感測器最近的幾站**（含距離），可直接挑一站當參考。
> 全部 77 站的資料在環境部自己的開放資料平臺（data.gov.tw 資料集 40448），
> 本頁已接成第三個來源＝「國家空品測站（環境部開放資料）」分頁，板橋在那裡查得到，但**需要 api_key**。

## 測項與圖表

- 加入測站後會自動讀取該站的 datastream 清單，產生**可複選**的測項勾選列；
  標「共同」的測項代表兩個來源都有，會疊在同一張圖上。
- **檢視區間**：載入後可在「連續變化」上方切 全部／7 天／3 天／1 天。
  這只縮小**顯示與統計的範圍**，不會重新抓資料（所以是瞬間的）。
  14 天的分鐘級資料擠在一張圖上看不出日變化，切到 1 天就很清楚。
  **圖表與下方所有統計面板用的是同一個區間**，不會出現「圖是 1 天、表是 14 天」的錯配；
  目前在看多久、已載入多久，按鈕下方都會寫明。
- **每個測項一張圖**，共用同一條時間軸；同一張圖裡多站以不同顏色區分。
- 細線＝微型感測器（3 分鐘值）；粗線加空心圓點＝國家空品測站（小時值）。
- 「重點測項」決定下方小時 pattern 與統計表要看哪一個測項（預設 PM2.5）。

## 分層統計與來源間偏差

圖表下方兩個面板都是針對「重點測項」計算的：

**分層統計** — 平日／假日 × 尖峰／離峰，每格給 `n`、平均、SD、中位數、IQR。
尖峰＝台灣時間 07–09 與 17–19；**假日只認週六日，未納入國定假日與補班日**。

**來源間偏差** — 只有在同時載入國家測站與微型感測器、且兩者有共同測項時才出現：

| 指標 | 意義 |
|---|---|
| 配對小時 n | 兩邊都有有效值的小時數 |
| bias（微型 − 國家） | 平均差值，附 95% CI 與相對百分比 |
| MAE / RMSE | 平均絕對誤差與均方根誤差 |
| Pearson r | 小時值的相關係數 |
| Bland–Altman | 差值對兩者平均的散布圖，含 bias ± 1.96 SD 一致性界限 |
| 濕度分層 | 用該微型感測器自身的 RH 切 < 70% / 70–85% / ≥ 85%，看正偏誤是否隨濕度放大（要一起勾選 RH 測項） |

配對方式：微型感測器先降頻成台灣時間的**小時平均**（有效筆數不足的小時整格排除），
再與國家測站同一小時的值配對，不做內插也不做時間位移。

> **這是偏差的描述，不是校正。** 兩者量測原理不同（光散射 vs 法規等級儀器），
> Bland–Altman 只描述兩個方法的一致程度，不能判定哪一邊「對」，
> 也不該拿 bias 去回頭修正原始曲線。
>
> ⚠️ **這個面板目前有已知的方法學問題，數字不要拿去下結論。** 兩個測點若不是並置（co-location），
> 差值同時混合了儀器差異與真實的空間濃度梯度，不能稱為 bias；逐時 PM2.5 的自相關也會讓 95% CI 過窄；
> Pearson r 不是一致性指標。修正項目列在 `CLAUDE.md` 的「下一輪必修」。

## 可分享的網址

加入測站後網址列會自動帶上參數，可直接加書籤或傳給別人：

```
https://<你的帳號>.github.io/air-observer/#dev=iot:13580653094,epa:板橋&params=PM2.5,O3&days=7&end=2026-08-19&focus=PM2.5
```

- `dev` — `iot:` 是微型感測器、`epa:` 是國家測站，逗號分隔（上限 3 站）
- `params` — 要載入的測項，逗號分隔
- `days` / `end` — 往前天數與結束日（台灣時間）
- `focus` — 小時 pattern 與統計表使用的測項
- `view` — 檢視區間（`1`／`3`／`7`；不帶就是全部）

舊格式 `#device=<編號>` 仍可開啟，一律視為微型感測器。

> **這台裝置會記住你加過的測站與上次的資料**：網址沒帶參數時自動回復上一次的清單，
> 並**直接畫出上次抓到的資料**（不會自動連網），狀態列會標明是幾分鐘前抓的、不是即時值；
> 要更新按「載入測站資料」。左欄下方有「清除記住的測站」（會一併清掉資料快取）。
> 日期區間與快取不符時不會套用快取，避免圖跟上方的控制項對不起來。
> 別人分享給你的連結**一定勝出**，而且會照舊直接抓最新的，不會用到本機快取。
> 若清單裡有「國家測站（環境部開放資料）」的站，回復時需要 api_key——沒存金鑰的話那一站
> 回不來，但**記住的清單不會被清掉**，貼上金鑰重新整理就會回來。
>
> **api_key 不會出現在網址裡**，所以分享連結不會外洩金鑰。
> 若嫌每次重貼麻煩，可勾「記住這支金鑰」存在這台裝置的瀏覽器裡（預設不勾，旁邊有清除按鈕）。
> 注意同一個 `<帳號>.github.io` 底下的所有網頁共用同一份儲存空間，**公用電腦不要勾**。

## 如果畫面顯示「無法連線到資料來源」

訊息會先自動診斷是哪一種：

- **「主機有回應，但沒有回 CORS 標頭」** → 用下面的 Worker 解。
- **「連不到這台主機或這個路徑」** → 不是 CORS，改 endpoint 才有用
  （例如 `sta.ci.taiwan.gov.tw` 從瀏覽器就是連不上，改用 `sta.colife.org.tw`）。

CORS 被擋的解法：

1. Cloudflare Dashboard → **Workers & Pages → Create → Worker**
2. 把 `worker.js` 全部貼上，**Deploy**
3. 回到網站 → 展開「資料來源與 proxy 設定」→ 在 **CORS proxy 前綴** 填入：

```
https://<你的-worker>.<你的帳號>.workers.dev/?url=
```

Worker 內建網域允許清單（只轉發 `sta.colife.org.tw`、`sta.ci.taiwan.gov.tw` 與 `history.colife.org.tw`），
不是開放式 proxy。免費方案每天 10 萬次請求，這個用途綽綽有餘。

## ⚠️ 這個 API 只保留最近幾小時的資料

**這是資料來源的設計，不是本頁的 bug。** 實測微型感測器 `13580653094` 的 PM2.5：
整條序列的 `@iot.count` 只有 121 筆、涵蓋約 2 小時；查 3 天或 7 天，拿到的還是那 2 小時。

加入測站後，左欄會顯示該站的**可查詢範圍**（例如「可查 08-19 05:00 ～ 07:00（約 2.0 小時）」），
載入按鈕下方也會在你選的天數超過保留期時先警告。

## 微型感測器的跨日資料

跨日的觀測值只在 <https://history.colife.org.tw> 的每日 ZIP 裡，而那些檔案
**每天每測項約 220 MB、內含全國約 1,370 萬列，而且 CORS 被擋**——瀏覽器不可能自己處理。
所以改成兩段式：

```
history.colife.org.tw（220 MB／天／測項）
   │  GitHub Actions（每日排程 ＋ 手動回填）
   ▼
scripts/hist_extract.py   下載 → 解壓 → 篩出指定裝置 → 輸出
   │
   ▼
data/iot/<裝置編號>/<YYYY-MM>.csv   每台裝置每月一個小檔
data/manifest.json                   有哪些裝置／月份／測項／時間範圍
   │  同源 fetch（無 CORS、無金鑰、手機可用）
   ▼
index.html   與 API 的近 2 小時合併成單一序列
```

- 合併以**分鐘**為鍵去重（兩邊的秒數都不固定），重疊的分鐘以 API 為準。
- 狀態列與圖例會**分開標示**兩段的筆數，例如「repo 歷史檔 17,526 筆 ＋ API 即時 121 筆」，
  不會合成一個看不出來源的總數。
- `data/` 還沒有資料時靜默略過，不會報錯；以 `file://` 直接開啟時讀不到相對路徑，
  本機測試要起一個 http server（例如 `python3 -m http.server`）。

> **「今天」為什麼常常是空的——以及怎麼補**
>
> history 站的日檔要等**隔天台灣時間 03:00** 才產出，而 API 只保留**約 2 小時**。
> 兩者中間最多差約 22 小時，所以在傍晚或半夜看，「今天」幾乎整天沒有資料。
> 這不是抓取失敗，也不是感測器離線。
>
> `api-append.yml` 每小時把 API 的滾動視窗併進 CSV，把缺口縮到最多 2 小時。
> **間隔不能拉長超過 2 小時**，否則會漏掉 API 已經淘汰的觀測值。
>
> **但排程本身不保證會跑。** GitHub 的 `schedule` 是盡力而為：2026-08-28 查證，
> `hist-daily` 在 08-27T21:00Z 那一次完全沒有觸發，`api-append` 一天該跑 12 次
> 卻只跑了 3 次。所以還有第二層保險——`hist-daily` 每次回看**最近四天**，
> 漏跑幾次隔天也補得回來。回看變寬不會變成多下載：已經填滿的日子
> （該日該測項 ≥ 1200 列）直接跳過，不會再拉一次 220 MB 的日檔。
>
> 圖上出現破碎的空白時，先看是哪一種原因：**來源掛掉**（Actions 執行紀錄裡有
> `::error::`）、**排程沒觸發**（Actions 裡根本沒有那個時段的紀錄）、
> **來源日檔本身殘缺**（例如 08-12 站方就沒有），或**感測器離線**。四者不同，
> 不要混為一談。

### 自己回填

repo → **Actions** →「回填 history 歷史資料（手動）」→ **Run workflow**，選一個模式：

| 模式 | 用途 |
|---|---|
| 探勘 ZIP 結構（dry-run） | 只印 ZIP 內容與 CSV 表頭前幾列，不寫檔 |
| 探測有哪些測項代碼 | 逐一試候選代碼，回報哪些真的是 ZIP |
| 存 API 快照（時區用） | 把 API 只留 2 小時的觀測值存起來，供日後驗證時區 |
| 時區判定 | 逐時剖面 ＋ 與快照逐筆比對 |
| 正式萃取 | 真的抓資料寫進 `data/` 並 commit |

> **檔名裡的測項代碼只有 `humidity`、`pm25`、`temperature` 三個。**
> 其他寫法（`pm2.5`、`pm2_5`、`PM25`、`pm10`、`temp`…）站方會回 **HTTP 200 但內容是 HTML 錯誤頁**，
> 不是 404。代碼猜錯會靜默抓到錯的東西，所以一定要先用「探測有哪些測項代碼」確認。

> **時效**：民生公共物聯網的資料服務據稱只提供到 2026-12-01（未向官方求證）。
> 要的歷史最好在那之前回填完。

> **會被限速**：同樣 14 天的區間，PM2.5 跑 10 分鐘、濕度跑約 50 分鐘（一小時內拉了約 6 GB）。
> 回填長區間請分批、隔開時間跑，別一次連續拉。workflow 有 120 分鐘上限，撞到就拆短再跑
>（寫入本來就以時間去重，重跑安全）。

### 來源本身也會缺資料

回填 2026-08-08～21 時，08-12 一列都沒有、08-11 與 08-13 明顯偏少（PM2.5 與濕度一致）。
對照下載到的檔案大小就知道原因不在本專案：那幾天**站方自己的日檔就是不完整的**
（08-12 只有 88 MB／547 萬列，正常日是 220 MB／1,374 萬列）。
缺的部分**維持缺漏**，不補值、不內插。

## 資料量沒抓滿怎麼辦

狀態列會直說，不會靜默略過：

- **「N 頁抓取失敗，資料不完整」** — 來源站擋了部分分頁請求（多半是短時間請求太多）。
  程式已對 429／5xx 自動重試三次；仍失敗就是這則訊息。縮短天數或減少同時載入的測項再試。
- **「這個來源只保留 …，比要求的 N 天短」** — 保留期不足（見上一節）。微型感測器若 repo 有歷史檔，
  訊息會改成「更早的部分改由 repo 的歷史檔補上」；沒有的話換日期也沒用。
- **「實際只涵蓋 X 天（要求 N 天）」** — 保留期夠、但這段期間感測器離線。
- **「無法連線」** — 訊息會分辨兩種情況：主機有回應但**沒有 CORS 標頭**（填 Worker 網址可解），
  或**主機／路徑根本不通**（要改 endpoint）。

## 已知限制

- **微型感測器不是法規等級儀器**。多為光散射法，環境部明示其數據不宜直接比對空氣品質標準，
  只適合看相對趨勢與時間 pattern；高濕度下對 PM2.5 常有正偏誤。
- **兩個來源疊圖是為了看偏差方向與時間結構，不是校正**。國家測站是小時值（已是該小時平均），
  微型感測器是 3 分鐘瞬時值，時間解析度不同，不可逐點相減。
- 圖上的顏色採 AQI 的 PM2.5 分段濃度值，但 **AQI 正式定義是 24 小時移動平均**，本頁畫的是小時平均，
  兩者不等價。AQI 配色只用於 PM2.5，其他測項改用單色深淺。
- 缺值不內插，時序中斷處直接斷線（門檻＝取樣間隔中位數的 2.5 倍，至少 20 分鐘）；
  小時有效筆數不足會以半透明標記（3 分鐘序列 < 5 筆；小時值序列不套用）。
- 單次查詢上限 3 站，避免對來源站造成不必要的負載。天數與測項越多，請求數越多（載入按鈕下方會先估算給你看）。
