    方法與限制
    
    
      
      
    1. 資料來源（三個）：
        （a）微型感測器——民生公共物聯網「智慧城鄉空品微型感測器」，全國約 10,999 點、2017 年 6 月起，
        https://sta.colife.org.tw/STA_AirQuality_EPAIoT/v1.0/。
        資料集文件寫 3 分鐘，但實測裝置 13580653094 是每 1 分鐘一筆；本頁一律以序列自身的間隔中位數推算，不寫死。
        （b）國家測站（環境部開放資料）——https://data.moenv.gov.tw/api/v2/（資料集 40448），
        77 站全有（含板橋）、每小時、可回溯約 4 天，需要 api_key。
        （c）國家測站 STA——https://sta.colife.org.tw/STA_AirQuality_v2/v1.0/，免金鑰，
        但這個服務只收錄 66 站（板橋、土城等不在其中）且只留近 2 小時。
        官方文件寫的 sta.ci.taiwan.gov.tw 從瀏覽器連不上，本頁改走 colife。
        (a)(c) 為 OGC SensorThings API v1.0。授權：政府資料開放授權條款第 1 版。
      2. 
      
    2. 跨日資料怎麼來：三個 API 都只保留近期觀測值（微型感測器與 STA 實測約 2 小時，開放資料約 4 天）。
        微型感測器的歷史值由 GitHub Actions 從 history.colife.org.tw 的每日 ZIP 事先萃取成
        data/iot/<裝置>/<月>.csv，網頁以同源方式讀回來，補在 API 那 2 小時的前面；
        合併以分鐘為鍵去重，重疊處以 API 為準，狀態列與圖例會分開標示兩段筆數。
        另有排程每 2 小時把 API 的滾動視窗併進 CSV，避免「今天」出現長達近一天的缺口。
        history 檔的時間欄位沒有時區標記，目前以台灣時間解讀；未經逐筆驗證前，
        狀態列會明講這件事（驗證完成後該提示自動消失）。
      3. 
      
    3. 編號比對：微型感測器依序試 properties/locationId、properties/stationID、完整 name、名稱片段；國家測站依序試 properties/stationName、name、properties/stationID、名稱片段。命中即停。
      4. 
      
    4. 時區：API 的 phenomenonTime 為 UTC，本頁一律轉為台灣時間（UTC+8）後才分組與繪圖。若 phenomenonTime 是時間區間（起/迄），取區間起點當作該筆的時標。
      5. 
      
    5. 分頁：SensorThings API 單頁上限 100 筆。本頁先以 $count=true 取總筆數再用 $skip 併發取回（上限 4）；若伺服器未回 @iot.count，改為逐頁跟隨 @iot.nextLink。單頁失敗會自動重試（僅對 429／5xx），仍失敗則計數並在狀態列標示「資料不完整」——不會靜默略過。
      6. 
      
    6. 兩個來源的可比性：國家測站是法規等級儀器（β 射線／震盪天平等）並經品保程序，微型感測器多為光散射法，靈敏度與準確度不同，環境部明示微型感測器數據不宜直接比對空氣品質標準，只適合觀察相對趨勢與時間 pattern；高濕度下光散射法對 PM2.5 常有正偏誤。兩者疊圖的用途是看偏差方向與時間結構，不是校正。
      7. 
      
    7. 缺值：不內插、不填補。中斷處直接斷線（斷線門檻＝該序列取樣間隔中位數的 2.5 倍，微型感測器至少 20 分鐘）。小時有效筆數不足（門檻＝min(5, ceil(每小時應有筆數 × 0.6))，隨該序列實際取樣頻率調整）標記為低樣本（半透明）；小時值序列本來每小時就只有 1 筆，不套用此標記。
      8. 
      
    8. 分層與偏差量化：分層統計與來源間偏差一律以小時平均為單位（兩個來源時間解析度不同，先降頻成小時才可比），n 是有效小時數；有效筆數不足的小時整格排除，不以任何方式補值。尖峰定義為台灣時間 07–09 與 17–19 時；假日只認週六日，未納入國定假日與補班日。Bland–Altman 只描述兩個方法的一致程度，不判定何者正確，bias 也不得回頭用來校正原始曲線。濕度分層使用該微型感測器自身的 RH。
      9. 
      
    9. 頁面版本：（回報問題時附上這串，可確認你看到的是不是最新版；手機請長按重新整理或清除快取以取得新版）。
      10. 
      
    10. 用途：個人資料探索工具，非法規依據。若要引用於論文或正式報告，應改用國家測站經品保程序後的數據，並註明資料擷取日期。
