    方法與限制
    
    
      
      
    1. 資料來源：民生公共物聯網資料服務平台。（a）環境部「智慧城鄉空品微型感測器」，全國約 10,999 點、3 分鐘更新、2017 年 6 月起，endpoint https://sta.colife.org.tw/STA_AirQuality_EPAIoT/v1.0/；（b）環境部「國家空品測站」，77 站、每小時、1998 年起，endpoint https://sta.ci.taiwan.gov.tw/STA_AirQuality_v2/v1.0/（同一服務內以 properties/authority 區分環境部測站與中研院校園感測器）。皆為 OGC SensorThings API v1.0，免 API key，授權：政府資料開放授權條款第 1 版。
      2. 
      
    2. 編號比對：微型感測器依序試 properties/locationId、properties/stationID、完整 name、名稱片段；國家測站依序試 properties/stationName、name、properties/stationID、名稱片段。命中即停。
      3. 
      
    3. 時區：API 的 phenomenonTime 為 UTC，本頁一律轉為台灣時間（UTC+8）後才分組與繪圖。若 phenomenonTime 是時間區間（起/迄），取區間起點當作該筆的時標。
      4. 
      
    4. 分頁：SensorThings API 單頁上限 100 筆。本頁先以 $count=true 取總筆數再用 $skip 併發取回（上限 4）；若伺服器未回 @iot.count，改為逐頁跟隨 @iot.nextLink。單頁失敗會自動重試（僅對 429／5xx），仍失敗則計數並在狀態列標示「資料不完整」——不會靜默略過。
      5. 
      
    5. 兩個來源的可比性：國家測站是法規等級儀器（β 射線／震盪天平等）並經品保程序，微型感測器多為光散射法，靈敏度與準確度不同，環境部明示微型感測器數據不宜直接比對空氣品質標準，只適合觀察相對趨勢與時間 pattern；高濕度下光散射法對 PM2.5 常有正偏誤。兩者疊圖的用途是看偏差方向與時間結構，不是校正。
      6. 
      
    6. 缺值：不內插、不填補。中斷處直接斷線（斷線門檻＝該序列取樣間隔中位數的 2.5 倍，微型感測器至少 20 分鐘）。小時有效筆數不足（3 分鐘序列 < 5 筆）標記為低樣本（半透明）；小時值序列本來每小時就只有 1 筆，不套用此標記。
      7. 
      
    7. 分層與偏差量化：分層統計與來源間偏差一律以小時平均為單位（兩個來源時間解析度不同，先降頻成小時才可比），n 是有效小時數；有效筆數不足的小時整格排除，不以任何方式補值。尖峰定義為台灣時間 07–09 與 17–19 時；假日只認週六日，未納入國定假日與補班日。Bland–Altman 只描述兩個方法的一致程度，不判定何者正確，bias 也不得回頭用來校正原始曲線。濕度分層使用該微型感測器自身的 RH。
      8. 
      
    8. 頁面版本：（回報問題時附上這串，可確認你看到的是不是最新版；手機請長按重新整理或清除快取以取得新版）。
      9. 
      
    9. 用途：個人資料探索工具，非法規依據。若要引用於論文或正式報告，應改用國家測站經品保程序後的數據，並註明資料擷取日期。
